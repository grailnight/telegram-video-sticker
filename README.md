# Видеостикер для Telegram (Android)

Приложение превращает видео или GIF в видеостикер или видеоэмодзи Telegram:

- WebM, кодек VP9, без звука, до 3 секунд, до 30 кадров/с, до 256 КБ
- стикер: одна сторона 512 px, вторая — не больше 512; эмодзи: 100×100
- прозрачный фон там, где его вырезает форма (скруглённые углы, круг или овал)

## Возможности

- **Область кадра** — рамка на кадре видео: двигается, тянется за углы и стороны, режим «Квадрат 1:1».
- **Шкала времени** — миниатюры всего ролика и окно фрагмента: двигается по шкале, края меняют длину.
  Кнопка «Просмотр» проигрывает выбранный фрагмент прямо в рамке.
- **Скорость** 0.5×–4× — длинный момент можно ужать в 3 секунды.
- **Туда-обратно** — фрагмент проигрывается вперёд и назад, стикер зацикливается без рывка.
- **Формат** — стикер 512 px или эмодзи 100×100.
- **Форма** — прямоугольник, скруглённые углы, круг/овал (с прозрачностью).
- **Подпись** — белый текст с обводкой сверху, по центру или снизу.
- **GIF на входе** — помимо видео.
- **Добавить в Telegram** — импорт стикера новым набором через Telegram (каждый импорт создаёт новый набор).

## Как пользоваться

1. «Выбрать видео или GIF» (или «Поделиться» из галереи → «Видеостикер»).
2. Выделить рамкой область, выбрать фрагмент на шкале, при желании — скорость, «туда-обратно», формат, форму и подпись.
3. «Конвертировать», затем «Сохранить…», «Поделиться» или «Добавить в Telegram новым набором».
4. Вручную стикер добавляется так: отправить `.webm` файлом боту [@Stickers](https://t.me/Stickers)
   (`/newvideo` для набора стикеров, `/newemojipack` для эмодзи).

## Сборка

Нужны JDK 17+ и Android SDK (platform 35, build-tools 35).

```
./gradlew assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk` (подписан debug-ключом, Android 8.0+).

Готовые нативные библиотеки лежат в `app/src/main/jniLibs`, поэтому NDK для обычной сборки не нужен.
Пересобрать их (нужны NDK, nasm и исходники libvpx):

```
git clone --depth 1 --branch v1.15.2 https://github.com/webmproject/libvpx.git /tmp/libvpx
ANDROID_NDK=$ANDROID_HOME/ndk/28.2.13676358 LIBVPX_SRC=/tmp/libvpx native/build.sh
```

## Как это устроено

1. Кадры фрагмента декодируются системным декодером (`MediaExtractor` + `MediaCodec`, GIF — через `Movie`).
2. OpenGL рисует каждый кадр: обрезка по рамке, масштаб, поворот, подпись, маска формы.
3. Готовые кадры складываются в память и кодируются libvpx (VP9, два прохода; при прозрачности —
   отдельный поток альфа-канала), затем пишутся в WebM собственным небольшим муксером (`native/stickerenc.c`).
4. Если файл больше 256 КБ, кодирование повторяется с меньшим битрейтом без повторного декодирования.

`native/test_main.c` — проверка кодировщика на компьютере без Android.
